# EtherCAT Workbench 功能点与约束

本文是项目功能、安全边界和实现约束的中文基准。修改或新增功能/约束时，必须同步更新本文；README 面向使用者，本文面向开发与维护。

## 产品与运行环境

- Windows 10/11、Python 3.11+；桌面 UI 只使用 Tauri 2 + React + TypeScript + Material UI + Emotion，Python 作为持久化硬件桥接进程；Real 模式固定使用官方 Windows wheel `pysoem==1.1.13`。
- 项目根目录提供可双击的一键启动脚本；已安装全局 pnpm 时直接使用，否则优先使用 Corepack 已缓存的兼容版本，仍不可用时再获取项目声明版本。首次启动自动安装前端依赖，并在失败时保留错误窗口。
- 应用名称统一为 **EtherCAT Workbench**，默认启动到 Real 模式。Real 是正常工作状态，不显示专门的模式标识；低频使用的 Demo/Mock 模式从“设置”菜单启用，并在启用期间持续显示 Demo 标识。
- Real 模式依赖官方 Npcap，需启用 WinPcap API-compatible Mode；项目和安装包不得捆绑免费版 Npcap 安装程序。
- 没有真实硬件时只声明 Mock/无硬件测试结果，不得伪造真实从站验证成功。

## 架构约束

- Python 硬件核心采用唯一 Master 状态机，状态阶段固定为 `disconnected/adapter_open/bus_scanned/pdo_configured/cyclic/faulted`。连接、扫描、断开、周期、恢复与复位只能通过该状态机提交原子转换；状态机必须校验合法来源状态和阶段不变量，周期状态只有在 Worker 确认安全停止或 generation 故障后才能清除；Bridge 和页面不得维护另一套可写的 `connected/slaves/cycle_running/session` 硬件状态。
- 每个成功或失败命令响应必须携带同一时刻的完整总线快照，至少包含 `mode/phase/adapter/connected/cycle_running/slaves/session_id/revision/last_error`。Tauri 为响应与事件注入当前 `host_generation`；React 按 `(host_generation, session_id, revision)` 单调接收完整快照，拒绝旧 generation、旧 session 或倒退 revision。React 只能用完整快照更新总线状态，禁止根据单个命令结果手工拼接局部硬件状态。心跳只传输进程遥测，不能推进前端 session。
- 桥接协议版本 3 使用当前 Tauri 实例创建的 Windows Named Pipe；消息采用 `UINT32 little-endian payload length + UTF-8 JSON` 分帧，单帧上限 8 MiB。同步双工 Pipe 的读取端必须先用 `PeekNamedPipe` 确认已有数据再读取，禁止用一个永久阻塞的同步读占住同一文件对象并使请求写入死锁。版本 3 要求成功和失败响应都携带完整 Master 快照。stdin 不得用于协议，stdout/stderr 只允许作为诊断日志输入，任何日志、乱码或第三方原生库输出不得进入协议流。
- `src/ethercat_debug_tool/protocol/commands.json` 是命令 lane、Host 超时、写入属性和队列上限的单一机器可读来源。Python Bridge、Tauri Host 与前端 Operation Store 必须拒绝未注册命令；新增功能不得在页面或任一层私自定义另一套超时、并发入口或写操作重试。
- 每个 Python 硬件进程 generation 采用 `starting/ready/busy/stalled/stopping/exited` 状态机。心跳只用于遥测，不能证明 Master Worker 健康：持有 GIL 的原生调用会让心跳停止，释放 GIL 的原生调用即使 Worker 卡死仍可能保持心跳。Named Pipe 建连最多等待 10 秒，不得因 Python 导入/启动失败无限卡住应用启动。
- 所有响应错误使用结构化错误对象，至少包含 `code/message/category/recoverable/session_invalidated/operation_result/request_id/method/session_id`。前端必须保留错误码；`CANCELLED` 显示为中性取消结果，不能降级成普通 `Error` 或红色失败。进程退出、传输中断或不可取消超时中的写操作必须进入 `unknown`，只读操作进入 `failed`；写操作不得自动重试，必须按寄存器/EEPROM安全规则重新读取验证。
- 命令引擎分为 control、metadata、hardware 三条 lane。control 用于状态、取消和关闭；metadata 只处理不持有 Master 的本地 Profile/ESI/SII 数据；hardware 最终只能进入唯一 EtherCAT Worker。Metadata 队列上限 8、hardware admission 上限 32、Worker 队列上限 32，队列满必须返回 `QUEUE_FULL`，不得无限排队或创建线程。
- 每次连接、断开、扫描、模式切换、recover/reconfig 和 ESC 复位均推进 session epoch。硬件请求和 Worker 异步事件均绑定提交时 session；Bridge 与 Master 状态机必须拒绝旧 session 事件，React 也必须丢弃旧 generation/session 的过程数据和进度事件。旧 session 请求、响应或事件不得修改新会话状态。寄存器写入计划继续额外绑定完整从站身份、配置地址和 60 秒有效期。
- React 的全部桥接调用必须经过统一 Operation Store。每项操作绑定 request、method、lane、mutating、session 和 page generation，并且只允许以 `completed/failed/cancelled/unknown` 之一结束；页面切换必须先推进 page generation、再渲染目标页面，目标页面初始化的请求不得被自身取消；session/host generation 更新时，携带该快照的响应操作可以正常收敛，其余旧操作必须统一失效。Worker stall 或进程退出也必须统一收敛所有非终态操作。全局忙碌状态只能由 Store 中有效的 hardware 操作推导，页面不得新增 `busyCount` 或独立 in-flight ref。
- 寄存器监视必须等待上一次请求终态后用 `setTimeout` 调度下一次；禁止用固定 `setInterval` 堆积请求。页面/profile/从站/session 变化后旧响应只能被丢弃，不能覆盖新上下文。
- GUI 线程禁止直接调用 pySOEM。PDO、SDO、EEPROM和寄存器请求统一进入独立 EtherCAT Worker。
- 同一个 Master 的所有 EtherCAT 请求必须串行调度；耗时操作不得阻塞 GUI，并应支持进度、取消或安全停止。
- 桥接请求采用分操作硬 deadline。底层原生通信开始后不可由 Python Future 取消；deadline 到达时必须由故障域之外的 Tauri 关闭旧 generation、终止其 Job/Python 进程并确认旧 PID 消失，再创建全新且保持未连接的 generation。禁止仅标记 Worker 失效、禁止重建线程后保留旧 Master、禁止要求用户重启整个桌面应用。
- Python Bridge 的异常事件必须先转换为 JSON 安全数据；单个事件发送失败不得终止事件转发线程。Bridge stdout 结束时，Tauri 必须立即失败所有在途请求并将界面切换为“通信核心已退出”，不得继续显示已连接或无限等待到请求超时。
- Tauri 必须区分 Python 真实退出、stdout EOF、stdout 读取错误和非 UTF-8 噪声；退出事件包含退出码、最后请求与 stderr 尾部。stderr 与退出诊断写入最多 1 MiB、保留一个备份的 `python-bridge.log`，不得再用无证据的统一退出文案覆盖根因。
- 运行中命令由 Tauri deadline、进程句柄和 generation 监督；Python 同进程心跳不得作为 Worker 健康判据。任何旧 generation 的响应或事件都不得改变新 generation 的 session、连接、从站、进度或 Operation Store 状态。
- Tauri 在 Windows 上必须把 Python 桥接子进程加入启用 `KILL_ON_JOB_CLOSE` 的 Job Object；宿主正常退出、被强制结束或崩溃时由操作系统回收桥接子进程，禁止遗留仍可能持有网卡 Master 的孤儿进程。
- Tauri 使用进程级命名互斥锁保证同一用户会话中只能运行一个 Workbench 实例；再次启动不得创建第二个窗口或第二个 Master。关闭应用窗口必须退出 Tauri 并有界关闭其 Python Bridge，最小化窗口不得触发退出。开发启动脚本只可按精确可执行文件路径、父子关系和项目标记清理本项目的失效 Tauri、Python Bridge 与 Vite 进程，不得按进程名泛化终止其他项目进程。
- Python Bridge 同时处理的请求线程必须有明确上限；达到上限时快速返回繁忙错误，不得无限创建线程。Worker 初始化失败必须立即失败排队及后续请求并发送 `worker_fatal`，不得留下永不完成的 Future。
- 通信核心或 Worker 退出时，前端必须统一结束全局 busy、自动扫描、EEPROM 独占进度和页面局部操作，清空失效的连接、从站与快照状态；后续桥接请求必须快速失败。通信核心退出信息必须保留并显示 `log_path`，提供直接打开日志位置的操作。
- 模式切换只有在旧 Worker 已确认退出后才能创建新 Worker，任何时刻禁止为同一进程保留两个可能访问网卡的 Master。
- 桌面退出先请求 Worker 和 Python 安全关闭；有界等待后仍被不可中断原生调用卡住时，只终止当前 Tauri 实例拥有的桥接子进程，禁止无限等待或遗留后台 Master。
- 保持 React UI、Tauri Host、Python Bridge、Application Services、Worker、Real/Mock Backend、Models、ESI/SII、EEPROM、Register、ESC Profile 分层，不把业务逻辑堆入页面组件。
- 自动化测试不得连接真实网卡或写真实 PDO 输出、EEPROM、寄存器。

## 已实现通信与 UI

- 网卡枚举、连接/断开、Npcap 错误提示、扫描、身份信息和 AL Status。应用启动完成后自动枚举一次适配器并立即填充网卡栏，但不得隐式打开网卡或扫描从站；用户点击“检测并扫描”后才逐个探测适配器。每个适配器必须独立记录耗时、错误和超时，并使用独立的 4 秒 Worker deadline；某个原生调用超过 deadline 时必须记录具体网卡并由 Tauri 回收、重建该 Python generation，禁止继续在状态未知的 Master 上探测。硬件发现失败不得使概览、寄存器目录或离线 EEPROM/ESI 功能不可用。
- 概览必须把当前总线阶段、最近通信错误和从站 AL 状态码同时以可读文字显示；设置中可在中文与 English 间切换 AL 状态名称、原因说明和排查建议。前后端复用同一份标准码集合，未收录标准码与 0x8000–0xFFFF 厂商自定义码必须明确区分。状态切换失败的后端诊断应包含各受影响从站的 AL Status、0x0134 状态码及已知含义。保留最后确认的总线快照时不得把暂时通信错误伪装成设备状态改变。
- 扫描时读取并缓存身份、ESC 型号、配置地址和 PDO 尺寸等静态信息；序列号直接读取 SII 身份字段，PDO 尺寸使用扫描结果，禁止为可选 CoE 0x1018 或 PDO 映射遍历等待长超时。普通状态刷新和状态切换完成后的更新只读取 AL 状态并复用缓存。
- INIT、PRE-OP、SAFE-OP、OP 使用四个直接切换按钮；支持只读状态刷新、手动 reconfig 和 recover。周期运行期间前后端均须拒绝状态切换、reconfig 和 recover；recover 的布尔返回值不代表恢复完成，必须重新读取目标从站并确认其存在、状态非 NONE 且 AL 状态码为 0。手动请求 SAFE-OP/OP 时必须先完成 PDO 映射；请求 OP 还必须先确认 SAFE-OP 并交换首帧过程数据，再执行 OP 状态校验。
- 普通 SDO 读写必须 `ca=False`；支持在线对象字典、ESI 回退和手动对象访问。
- SDO 读取按用户选择的数据类型解码；写入后必须自动读回并逐字节比较，只有一致时才显示验证成功。
- 显示 PDO Entry 名称、类型、字节/位偏移；支持周期过程数据、Actual/Expected WKC、超时与错误计数。
- PDO 输出遵循“监视模式 → 输出控制模式 → 待应用 → 应用输出”，默认不得写硬件。
- 启动周期通信必须在同一个 Worker 中依次完成 PDO 映射、全总线 SAFE-OP、首帧交换、全总线 OP 验证；停止和周期故障必须优先请求 SAFE-OP，控制任务不得被超期 PDO 周期饿死。
- PDO 输出只有 Worker 确认成功后才能显示“已应用”；切换从站、页面或断开时必须清除旧目标数据，并关闭寄存器写入模式和监视。
- 新 UI 主要设计分辨率为 `2560×1440` 与 `1920×1080`，兼容下限 `1280×720`；采用带文字的紧凑一级功能导航、从站上下文栏和单一内容画布，不再平铺主页签。当前仅显示概览、寄存器、EEPROM 三个重点入口，CoE 对象、PDO 映射和在线 I/O 暂时隐藏但保留实现。状态同时使用文字和图标，不能仅依赖颜色。
- 禁止显示 WebView/浏览器默认右键菜单。概览、寄存器和 EEPROM 页的从站项统一提供“烧录 EEPROM”自定义右键菜单并打开快速烧录弹窗；弹窗从最近成功烧录记录、项目固定 `xml列表` 或文件选择器加载 XML，完成目标生成、容量和周期停止检查后才可写入。弹窗打开后必须在未选择 XML 时就展示当前从站的 Device、ESC 和 EEPROM ConfigData/PDI 信息，并用不同标题、颜色和来源说明区分“设备实际值”与“选中 XML 待烧录目标”，不显示“PDI 通用解码”字段。最近记录按原 XML 路径、Device 与实际 ConfigData 保存，最多展示 20 项；双击最近或固定列表中的 XML 必须用资源管理器定位其文件。每个 XML 项只显示一个收藏按钮，最近项点击后收藏到固定列表，固定项点击后取消收藏但不得删除磁盘 XML；最近/固定页签及收藏状态必须跨弹窗和软件重启保留。固定列表必须逐个展示 XML 中的 Device、Product Code 和 ConfigData 摘要，不设置“推荐匹配”字段。
- 设置窗口按“通用/关于”组织；关于页显示产品简介、应用版本、通信核心、许可证、GitHub 项目与问题反馈入口。外部链接必须限制为项目维护的白名单地址并交由系统浏览器打开。
- 从站和全总线状态切换只在对应概览中显示；周期、WKC、超时和错误详情只在“在线 I/O”中显示。状态栏只保留连接、当前目标和简洁总线健康信息。
- ESI 支持单 XML、多 Device、拖放/选择/最近文件；设置自动保存，日志包含轮转 JSONL 和写操作 `AUDIT`。

## EEPROM 安全规则

- 支持完整读取、Smart View、带 ASCII 列的只读 Hex View、仅 BIN 备份、ESI XML 自动生成 SII 完整目标镜像以及从备份恢复；严禁把 XML 文本字节直接写入 EEPROM。EEPROM 页面按“烧录目标、操作与条件、Smart View、进度与结果”组织；Smart View 在 XML/Device 变化后实时显示目标 SII 类别、类型、偏移、长度和内容预览，切换从站时自动选择匹配 Device 并恢复目标预览，完整读取后补充最近读取时间、身份、容量、结构、SHA-256、差异字节和首个差异偏移。同一总线会话中，离开再返回 EEPROM 页面必须保留各从站最近一次完整读取与 Hex View；host generation 或 session 改变后缓存失效。
- XML/Device 与目标从站的 Vendor ID、Product Code、Revision 任一不符时，页面必须明确列出不符字段；常规的 ESI→SII 转换范围说明不得显示为失败或容量降级警告，只有 PDO/DC 等关键类别实际降级或省略时才使用警告状态。
- SII 固定区按 SSC 兼容布局生成：ConfigData 头与 CRC、身份、标准邮箱（MBoxOut/MBoxIn → 0x30/0x34，宽 2+2 字节）、Bootstrap 邮箱（BootStrap → 0x28，缺省清零）、标准/引导邮箱协议字（0x38/0x3A）、EEPROM Size/Version 与保留区清零；SyncManager 类别类型码 1/2/3/4（MBoxOut/MBoxIn/Outputs/Inputs），PDO 头 NameIdx 为 UINT16，DC 条目按 CycleTimeSync0/Factor0/Shift0/CycleTimeSync1/Factor1/Shift1/AssignActivate/NameIdx/DescIdx 布局并解析 ESI Factor 属性，General 类别端口描述字节位于偏移 16。SSC 风格别名 `MBoxOut`/`MBoxIn` 与全小写形式等价。
- PDO 类别按保真阶梯编码：带条目名称 → 无条目名称（超过 SII 字符串表 255 项上限时）→ 省略；DC 优先级高于 PDO 条目名称，功能字段优先于名称。省略或降级原因必须随目标报告明确列出并包含实测字节数与容量，仅有结构有效的目标才能烧录。
- 原始 BIN 备份不得依赖 SII 解析成功；损坏镜像仍保存逐字节 BIN，不生成 JSON 元数据。XML 文件或 Device 改变后，旧生成目标立即失效，并立即从当前选择重新生成；只有有效目标才能烧录。
- 用户选择的 XML/Device 完整决定目标，不从旧镜像合并 Serial Number、Station Alias 或私有数据。身份不匹配只作信息展示；XML/SII 无法生成、镜像容量不符或通信失败才阻止烧录。用户可将 XML 的前 10 byte ConfigData 临时改为任意合法十六进制值，SII 生成器必须用修改后的内存副本生成并烧录目标，禁止覆盖或回写原 XML。界面同时解码当前 EEPROM 与本次目标的 ConfigData：PDI Control 显示 `0xNN` 和来自 `PDI.md` 的通用模式含义，含义不随 ESC 型号改变；未列出的组合不添加“保留”等推测标签，真正未收录的组合显示“含义未收录”。PDI 差异和芯片对应关系仅供用户判断，不显示危险/相同/变化结论，也不得据此阻止烧录。
- 烧录按钮直接标为“烧录”，仅在已选择从站、周期停止、XML 目标有效且已知容量不冲突时启用；烧录与 BIN 恢复进入独占操作后必须先自动请求目标从站 INIT 并复核成功，不要求用户预先手动切换。容量条件分为未比对、未知、一致和不一致四态。禁用按钮必须通过条件清单和 ToolTip 解释原因。操作期间采用跨“自动切换 INIT、读取当前、写入校验、稳定等待、完整回读、复位、重新加载”的单调总进度，不得在阶段切换时回退。烧录和恢复不自动创建备份，用户通过独立“备份 BIN”操作按需备份；备份完成后直接显示完整保存路径并提供打开位置入口。“完整读取”只刷新 Smart View/Hex View，“备份 BIN”读取并保存文件，页面必须明确说明差别。烧录仍须先全量读取当前镜像以计算差异 Word，但不落盘。仅写差异 Word；分批回读、不可跳过的稳定等待、全容量重读、逐字节比较、目标/回读 SHA-256、SII 结构与 XML 语义校验必须全部完成。任一字节不同均不得显示成功。普通结果仅显示成功/失败与关键结论，SHA-256、复位、首个差异和重新加载信息放入技术详情；错误、取消和校验失败统一显示在进度结果区，不重复弹出通用错误框。
- 镜像校验成功后，默认独占 Worker，以三个连续且独立的 FPWR 将 `0x52`、`0x45`、`0x53` 写入 8-bit 寄存器 `0x0040`。三帧之间不得插入任何请求。镜像校验、复位发送、重新发现、重新加载复核分别报告；复位掉线不反向改写镜像校验结果。
- EEPROM 进度操作名统一采用 `eeprom-*`，所有阶段在前端视为同一个全局独占操作；Bridge 在烧录/恢复请求进入硬件队列前取得 EEPROM 独占权，独占期间其他硬件命令必须立即返回 `EEPROM_BUSY`，不得排队到 Host deadline。期间禁止切页、换从站、连接、断开、扫描和切换模式。读取当前镜像阶段允许安全取消；首个 EEPROM Word 开始写入后必须关闭取消入口，并不可中断地完成写入、稳定等待、完整回读及复位复核，避免留下任意部分镜像。
- EEPROM 复位后的重新发现采用有界轮询（默认最长 5 秒、250 ms 间隔），不得固定等待一次后只扫描一遍。结果必须同步回全局从站状态；未重新发现时清空旧从站快照，禁止界面继续显示复位前状态。自动匹配 XML Device 只在 XML 或从站身份变化时执行，用户手动选择 Device 后不得被同一身份上下文立即覆盖。
- ESI→SII 仅声明已经实现和测试的标准元素；厂商私有 Category、完整自定义 DataTypes、EoE/FoE 等未支持内容必须明确报告。

## ESC Profile 与寄存器

- `chip_model` 与 `register_family` 分开建模。E101/E252/E253 是独立国产 ESC，分别兼容 ET1100/LAN9252/LAN9253 寄存器族，但不得显示成原厂芯片。
- E101、E252、E253、原厂 ET1100、LAN9252、LAN9253、Generic ESC 必须为独立 Profile。国产型号仅依据 ESI 型号文本或 `0x0E00` 芯片类型识别，不用 FMMU/SM 数量或 RAM 范围猜测；芯片类型寄存器需兼容 16/32 位及 PDI 大小端返回形式。
- E101 完全按 ET1100、E252 完全按 LAN9252、E253 完全按 LAN9253 处理，分别复用对应原厂的完整寄存器 profile、资源数量、地址空间和安全规则；不得再为三者保留“私有寄存器未验证”的降级限制。LAN9252/E252 的 Process RAM 为 `0x1000–0x1FFF`、FMMU 3、SM 4；ET1100/E101 与 LAN9253/E253 的 Process RAM 为 `0x1000–0x2FFF`、FMMU 8、SM 8。
- 寄存器目录以调查包的完整芯片 Profile 数据为准，定义唯一键为 `profile + address_space + address`；E101=ET1100、E252=LAN9252、E253=LAN9253 的已调查寄存器集合完全同构，但 UI 仍展示实际国产型号。
- 寄存器目录和单项定义属于本地只读 Profile 元数据查询，必须复用已加载的 Profile 数据库，并独立于硬件命令串行锁返回；扫描、状态切换或 EEPROM 长操作不得阻塞 LAN9252/LAN9253 目录加载。
- 目录同时展示 `esc_core`、LAN925x System CSR、HBI、PHY 和 RAM 等地址空间的文档项；只有 `esc_core` 且明确允许 EtherCAT 主站访问的已知项可由 FPRD/FPWR 读取或写入。已知项必须用 definition_id 在当前从站 Profile 内解析，禁止仅按地址匹配。
- 页面必须显示寄存器地址空间、主站权限、默认/复位值、状态限制、保留位规则、副作用、来源可信度和位字段权限。含混合权限、保留位、复位、PDI、SyncManager、DC、EEPROM 或特殊副作用的项默认禁止普通整寄存器写入。
- 所有 `_fprd/_fpwr` 只能由 RegisterService 封装，成功条件 WKC=1。默认只读，写前重读并显示目标从站、地址、当前值、目标值、变化掩码和最终字节。
- 寄存器写入计划必须绑定当前总线会话、从站完整身份和配置地址，并在 60 秒后过期；确认界面显示秒级倒计时，过期后自动禁用执行并要求重新生成。连接、断开、扫描、模式切换、recover/reconfig 或 ESC 复位后，旧计划必须失效，禁止把旧确认写到同位置的新从站。
- 区分 RO、RW、WO、W1C、W1S、自清零和易变语义；RW 写后比较，特殊类型做语义验证。未知地址原始写入允许但必须警告，所有写入进入审计日志。
- 错误计数器按端口分别定义为 1 字节 WAC 寄存器（RX 0x0300–0x0303、TX 0x0304–0x0307，写入任意值清零）；标准目录同时收录 PDI Control 0x0140、PDI Configuration 0x0150、AL Event Mask 0x0204、AL Event Request 0x0220（W1C）。
- 寄存器页原始地址输入 `0x0130` 与 `0130` 一律按十六进制解析，避免十进制误读；原始工具的读写宽度同时约束读取长度与写入 HEX 字节数，二者不一致时后端拒绝生成计划。
- 寄存器页以标准寄存器搜索/分组和主从详情为默认入口；选择已知寄存器自动采用定义地址、宽度与访问语义并读取，原始地址和写入工具默认折叠。WO 不得预读；W1C/W1S 以操作掩码表述，不得误称最终值。
- 概览页允许用户为每个从站手动选择寄存器 Profile（ET1100、LAN9252、LAN9253），用于决定寄存器目录和安全规则；检测到的 ESC 型号必须同时保留显示，手动选择不得伪装为硬件识别结果。E101/E252/E253 分别映射到 ET1100/LAN9252/LAN9253，界面不单独显示为可选项。
- 当检测到 E101/E252/E253 时，概览和寄存器页必须明确说明其实际国产型号及对应的同构目录；目录选择仅影响本地文档与安全规则，不得改变或覆盖硬件识别结果。
- 寄存器监视采用固定/取消固定模式，支持暂停、移除、清空和刷新周期；同一页同一时刻最多一个监视请求在途，监视轮询不得反复切换全局忙碌状态，失败后暂停。监视值变化须短暂高亮，列表不显示恒定且无诊断价值的 WKC=1 列。

## 版本、构建与发布

- 协议/调度/Operation Store 变更必须包含故障测试：分帧截断或超限、队列满、Worker 启动失败或原生调用卡死、进程/传输退出、多在途请求分别收敛、晚到响应、session/page/profile/从站快速切换，以及写操作结果 `unknown`。自动化测试只使用 Mock 或内存传输，不得触碰真实网卡。

- 发布只允许使用 Tauri 2 的 Windows bundle 流程；不得恢复旧桌面框架、旧冻结脚本或旧安装器工程。
- 只有用户明确要求发布时才增加版本号、执行完整测试和原生构建；GitHub Release 与标签代表不可变版本快照。
